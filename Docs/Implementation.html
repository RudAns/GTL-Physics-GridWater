网格水模拟：UE5 落地要点

对应工程 GTL-Physics-GridWater（UE 5.8，C++，不改引擎）。按数据流顺序列出《海狸浮生记》式网格水的每一步做法、关键常数和踩过的坑，可以直接对照源码搬进自己的项目。原理、原作代码分析与业界方案对比见 Research.html。

1. 总览

整个系统分成三层：纯 C++ 的模拟（FWaterSim，不依赖任何 UObject），把模拟结果写成浮点纹理的胶水层（AGWWorld），以及读纹理的两个材质（水面、地形）。建筑不直接改水深，只向模拟写约束；渲染不读模拟内存，只读纹理。这样模拟可以在任何线程、任何频率运行，换成 GPU 实现时上层不用改。

2. 数据布局

单层（2.5 维）网格，96 × 72 格，每格 1 m 见方，地形高度以“格”为单位取整数。所有字段是长度为 N 的平铺数组（结构数组 SoA），四向流量是 N×4。方向编号 0=+X、1=+Y、2=−X、3=−Y，对向为 (k+2)&3。

数组类型含义
Groundfloat地形顶面高度（格）
Solidfloat建筑附加的实体高度（堤坝、防洪闸整数部分）；地板 = Ground + Solid
InflowLimitfloat< 0 表示无；否则来水必须高出本格地板这么多才能进入（大坝 0.5，防洪闸小数部分）
DirLimit / Blockedint8 / uint8单向阀只允许沿该方向进出；关闭的阀完全不进不出
Drainuint8地图边缘的出口格，向外的流量视为流出地图
Depth / Concfloat水深（格）/ 污染度 0–1
Flow / Efffloat ×4四向出流（格³/秒）/ 有效出流（出流 − 0.8 × 对向流），后者是原作惯性项和污染平流的输入
VelX / VelYfloat由管道通量估算的流速（Mei 2007 公式），供流速视图、箭头、水面法线
Sat / EvapMod / Moist / SoilCuint8 / float聚簇饱和度、蒸发倍率、灌溉湿度（0–16）、土壤污染（0–1）

账本 FGWLedger 累计注入、流出地图、蒸发、抽取的水量和污染物量。守恒误差 = 网格内总量 −（初始 + 注入 − 流出 − 蒸发 − 抽取）。默认设置下误差约 1e-3 量级（float 累加误差），这一项是验证每次改动有没有破坏守恒的最快手段。

3. 一个子步

子步时长 0.3 s，与原作一致（0.6 s 一个 tick，每 tick 两个子步）。前四步都用 ParallelFor 按行并行，每个任务只写本格，读邻格时只读上一阶段的结果，所以不需要锁。

① 出流

// Prev = Eff[i][k]：原作把“有效出流”作为惯性项带到下一子步
base = Prev * damp                 // 0.999（原作）/ 0.95（强阻尼）/ 1.0（半隐式摩擦时）
dh   = Head(i) - Head(j)           // Head = Ground + Solid + Depth；出地图方向按 Ground-2 计
if (j 有流入限制 L) {
    above = Head(i) - Floor(j)
    软硬坝：above < L        → f = base - 衰减量（硬坝区最多 0.02，HardDamOffset 0.05 内线性过渡）
           above < L + 0.1  → 增量按 (above-L)/0.1 打折
    硬截断：above < L        → f = 0
} else if (目标干燥且同高) dh -= 0.1   // 漫流阈值
f = base + 2.25 * dt * dh           // WaterFlowFactor = 2.25
半隐式摩擦：f /= 1 + dt * 0.6 * |Prev| / max(d, 0.05)
f = max(f, 0)
// 四向算完后：若 Σf·dt > d，四向同乘 K = d / (Σf·dt)

K 缩放是守恒的关键：每份通量只从一个格子减去、加到一个格子上，且不会抽干到负值。关掉它（演示里的 F1）后，负水深被截断为 0，等于凭空造水。

② 水深、有效出流、流速、蒸发

收集式更新：d' = d + dt·(Σ入 − Σ出)，同时写 Eff = max(0, 出 − 入·0.8)。蒸发每秒扣固定深度：水深低于 0.02 格时 0.001，否则 0.0001，乘以按聚簇饱和度查得的倍率和演示用的时间压缩倍率（×25）。蒸发带走的水按本格浓度带走污染物，记入账本。

③ 污染平流

// 原作：保留旧水的浓度，按体积混入“有效入流”
recv = Σ Eff[j→i]·dt;   C' = (C·(d' - recv) + Σ Eff[j→i]·dt·C_j) / d'
// 改进：污染物质量与水量用完全相同的通量
M' = C·d - 蒸发量·C - Σ Flow[i→j]·dt·C + Σ Flow[j→i]·dt·C_j;   C' = M' / d'

原作格式用的“有效出流”和水深更新用的完整流量不一致，所以污染物总量会漂移；改进格式在账本里误差为 0（float 误差内）。两者都是一阶迎风格式，结果有界。

④ 门控扩散

对每对相邻湿格交换 0.45·dt·0.5·w·(C_j − C_i)·min(d_i, d_j) 的污染物质量，交换量对称，所以守恒。权重 w：布尔门控（原作）要求净流量 < 0.125 且水面高差 ≤ 0.1，坝顶薄层（水深 ≤ 1 且有流入限制）不扩散；平滑门控用 smoothstep 在阈值附近过渡；无门控时 w = 1，可以看到污染逆着急流爬向上游。

4. 建筑即约束

所有建筑都归结为下面几种模拟原语，每次建造、拆除、调高后重算一遍约束数组（ApplyConstraints，O(建筑数)）：

建筑原语写入
堤坝实体障碍Solid = LeveeH（1–3 格，整排可调）；建造时移除格内的水并记入账本
大坝流入限制InflowLimit = 0.5
防洪闸实体 + 流入限制高度 H 的整数部分写 Solid，小数部分写 InflowLimit，步长 0.05，界面每次调 0.25
自动阀方向限制 + 开关DirLimit = 朝向；自动模式每子步读上游格污染度（四舍五入到 0.01），超过阈值（默认 5%）写 Blocked
水泵抽水每子步从自身和四邻中最深的格抽 0.45 格³/秒，清水与恶水分开计数

整排连接与同步

同类、四邻相接、且（闸门、阀门、大坝）流向轴相同的建筑视为同一排（SameRun）。这条规则同时用于三件事：

  • 外观合并：闸门和阀门只在没有同排邻居的一侧立柱，闸板和横梁延伸到格边，相邻两格拼成一整块（Joined 判断左右邻居，LeafW / LeafOff 记录闸板宽度和偏移，动画时沿用）。建造或拆除后重建自身和四邻的外观（RebuildAround）。
  • 新件同步：新放的一件如果和已有的一排相接，直接继承那一排的高度和阀门模式。
  • 整排选中与调整：查看模式下点击建筑，用广度优先搜索取出整排（ConnectedGroup）；调高时以点中的那一件为基准，整排统一设为同一个新高度（AdjustGroupHeight）。选中框用一个 ISM 画半透明盒子。

5. 季节与水源

演示把 1 天压缩为 60 秒模拟时间（×1 速度下约 20 秒），周期为温和季 4 天、危险季 2 天，危险季在干旱和恶水潮之间交替（可手动切换）。水源每子步注入 强度 × 修正 × dt，按水源污染度混入。

干旱：开始前半天线性降到 0，干旱期间为 0，结束后半天线性回升
恶水潮：t < 0.5 天   C = 0.5 + 0.5·sech(17·(t − 0.5))
        结束前 0.5 天  同一曲线以剩余时间代入
        其余时间       C = 1

注意 sech 曲线在前三分之一几乎平在 50%，最后一段才陡升到 100%。这意味着恶水潮第一刻流出的水就超过了灌溉失效（约 53%）和土壤污染（50%）的阈值，截流必须在危险季开始之前完成，这也是游戏性的来源。

6. 派生场

每 2 个子步（一个 0.6 s tick）更新一次，均为单遍局部计算，开销可以忽略：

  • 聚簇饱和度：湿格的 3×3 有水格计数（含自身），再与四邻的计数减一取大，上限 8。只看邻居的计数，不会逐 tick 传播。
  • 蒸发倍率：n = 10 − s，倍率 = 0.0595n² + 0.101n + 0.72，孤立水坑约 ×6.45，大湖内部约 ×1.16。
  • 灌溉湿度：相邻清水提供 2 × 饱和度的初值，向高处每升一格扣 6；其他格取八邻域湿度减 1（对角 1.414）。上升每秒最多 6.66，下降每秒 1.25。污染度超过 1% 开始削减，约 53% 时完全不灌溉。
  • 土壤污染：污染度超过 50% 的水使 7 格范围内的土地变为污染土（向高处每格扣 5），污染每秒上升 0.066、消退 0.033。

作物和树木读湿度和土壤污染：土壤污染 > 0.4 时约 0.3 天死亡，缺水时作物约 1.2 天、树木约 2.5 天死亡，新温和季开始时补种。作物只种在开局时已被灌溉的格子上。

7. 水面渲染

水面是一张一次建好、之后不再修改的程序网格：每格一个顶面四边形和四个侧面四边形，共 20 个顶点。所有顶点的 Z 都是 0，真实高度由材质的世界位置偏移（WPO）从数据纹理读取。UV 通道约定：

通道内容
UV0格中心的纹理坐标
UV1.x角色：0 顶面，1 侧面上沿，2 侧面下沿，3 撑包围盒的退化三角形
UV2角点符号 (±1, ±1)
UV3侧面朝向 (dx, dy)

顶点着色器里的三条规则

  • 角点平均：顶面角点取本格和角上另外三格中“湿、且水面高差 < 0.45 格”的水面平均值。缓坡上的水面因此连成光滑斜面，瀑布这样的大台阶保持锐利，由侧面补上。侧面下沿用同一个函数在邻格上求值（角点符号沿侧面方向取反），保证上下缝严丝合缝。
  • 干格收起：干格的顶面压到地板下 8 cm，所有侧面退化成零面积，否则会在崖壁上挂出一层“水墙”。
  • 防止共面：湿格水面至少高出自身地板 3 cm；侧面整体沿朝向外推 1.5 cm。这两条消除了薄水面与地形、瀑布与崖壁之间的深度冲突闪烁。

前后两张纹理分别算出高度再按子步进度插值，水位变化在每帧都是平滑的。像素着色器用世界坐标双线性采样（纹理设为双线性过滤），法线用 cross(ddx(P), ddy(P)) 从位移后的几何求出，再叠加随流速滚动的法线扰动。泡沫只在快速深水和瀑布侧面出现，噪声用平滑函数，不要用按格取整的哈希噪声：随时间平移的方块噪声在画面上就是闪烁。

数据纹理

三张 PF_A32B32G32R32F 瞬态纹理：TA0 / TA1 轮换保存前一子步和当前子步的水面状态，TB 保存流速、湿度和土壤污染。用 UpdateTextureRegions 上传，源缓冲要在渲染线程用完前保持有效，做法是拷贝一份，在回调里释放。96×72 的 RGBA32F 一张约 108 KB，每子步上传的开销可以忽略。

8. 交互：拾取与整排选中

  • 拾取：不用物理碰撞，沿鼠标射线以 8 cm 步长在高度场上步进，第一次低于“地板 + 水深”时命中。命中点明显低于该格顶面时说明打在侧面上，同时返回射线前一格（OutFaceCell）：堆土工具用前一格，像体素游戏一样在点中的侧面前方放块，所以被近处台阶挡住的一格小坑也能填上。
  • 建造朝向：自动阀、大坝、防洪闸在光标所在格有明显流速时自动沿水流方向放置，按 Z 旋转后改为手动。
  • 整排操作：查看模式点击建筑选中整排；[ ] 或 Shift+滚轮整排调高，M 切换阀门模式，Delete 拆除，Esc 取消。没有选中时，[ ] 作用于光标下的那一排。

9. 测量与自测

powershell -File Tools/iterate.ps1 [-Assets]：编译编辑器模块，可选地用 build_assets.py 无头重建材质（HLSL 都写在脚本里），然后以 -game -RenderOffScreen -GWCapture=<目录> 离屏运行一个步骤脚本。脚本通过 InputKey(FInputKeyParams(...)) 注入按键、用 ProjectWorldLocationToScreen + SetMouseLocation 移动鼠标，走的是和真实输入完全相同的处理路径，共 34 项检查，日志里搜 GWTEST：

  • 镜头：R / Shift+R 各转 45°、滚轮缩放、WASD 平移；建造：悬停拾取、点击放防洪闸、相邻闸门同步高度、点击选中整排、[ ] 整排调高、拖动建堤坝、拆除；阀门：点击选中整排、M 三种模式。
  • F1–F7 原理开关切换与还原、视图切换、暂停与倍速、挖掘与堆土。
  • 恶水潮中所有上游被污染的阀门都关闭、水库污染度 < 5%；默认设置下守恒误差 < 0.5；关闭 K 缩放后误差明显增长。
  • 另有两张暂停状态下相隔 0.3 秒的瀑布近景截图，用于比对台阶处是否闪烁。

10. 坑点清单

  • F1–F5 被引擎占用：BaseInput.ini 的 DebugExecBindings 把 F1–F5 绑成线框、无光照、着色器复杂度等视图模式，Shift 也绑了调试快捷键。在 DefaultInput.ini 里写 [/Script/Engine.PlayerInput] !DebugExecBindings=ClearArray。
  • 自定义节点读不到 .w：向量参数默认输出 RGB，连到 Custom 节点要用 "RGBA" 输出。
  • ISM 用的材质要勾 used_with_instanced_static_meshes，否则会退回默认材质（选中框曾显示成灰黑色方块）。
  • 程序网格的包围盒：所有顶点 Z=0 时包围盒是扁的，WPO 抬起来后会被错误剔除。加一个退化三角形把包围盒撑到可能的高度范围。
  • 光照：这个规模的俯视角场景不需要 Lumen，工程里设 r.DynamicGlobalIlluminationMethod=0，用天光立方体贴图加 SSR，程序网格也不用生成距离场。
  • 守恒账本要记全：建堤坝、堆土会移走格内的水，必须记入“抽取与移除”，否则守恒误差会误报。
  • Interchange 路径：用 Interchange 重新导入贴图会把源文件的绝对路径写进 .uasset。资产脚本只在贴图不存在时导入一次。

11. 移植清单

  1. 复制 WaterSim.h/.cpp（只依赖 Core 的 ParallelFor），按自己的地形填 Ground，标出 Drain 出口格。
  2. 每帧以固定步长调用 Substep(0.3f)，每两步调用一次 UpdateDerived(0.6f)；水源、水泵在子步前调用 AddWater / RemoveWater。
  3. 建筑系统维护一张“格 → 建筑”表，变化后重算约束数组；需要整排操作时复用 SameRun / ConnectedGroup 的规则。
  4. 复制 BuildWaterMesh 和 build_assets.py 中的 WATER_WPO / WATER_COLOR / WATER_NORMAL，每子步上传两张数据纹理并设置 Alpha。
  5. 先用账本确认守恒误差接近 0，再调视觉。网格更大时把四个子步改成计算着色器（结构不变：出流 → 水深 → 平流 → 扩散），水深和流量保持 32 位浮点。
